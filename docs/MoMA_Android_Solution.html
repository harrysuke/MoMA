Product proposition

MoMA is a two-sided gig marketplace. Coaches publish lessons and control their availability; students and gyms discover, match, book and pay for training; moderators keep the marketplace safe and trustworthy. Revenue comes from a 10–20% commission per lesson, optional coach subscriptions and targeted advertising.

First beachhead: one BJJ gym hiring four specialist coaches. Broad student marketplace and community features follow once the weekly program is staffed and running.

Design principles

  • Trust before transaction: verified profiles, transparent pricing, reviews and disputes.
  • Server-authoritative money: booking and payment state are never decided on the device.
  • Offline-first reads: Room is the local source of truth with a visible "saved data" banner.
  • Role-aware by default: every screen and API call is scoped to student, instructor or admin.
  • Accessible mobile UX: 48 dp touch targets, TalkBack labels, scalable text, clear status chips.
Recommendation: keep the client thin and the rules on the server. Supabase Edge Functions own matching, booking holds, commission, Stripe PaymentIntents, payouts and notifications; Android only renders state and collects intent.

Booking & payment sequence — server-authoritative

1
Browse and matchCached listings render from Room; online results refresh in the background with a "saved data" banner.
2
Select an availability slotPOST /functions/v1/create-booking. Edge Function atomically checks the slot in a transaction and holds it for 10 minutes.
3
Create pending bookingStripe PaymentIntent created with application_fee_amount = resolved 10–20% commission. Client receives bookingId + clientSecret; booking is PENDING_PAYMENT.
4
Pay with Stripe Android SDKCard details go straight to Stripe. No PAN or CVV ever touches MoMA SQLite or the app's logs.
5
Webhook confirms and settlespayment_intent.succeeded → booking CONFIRMED, slot BOOKED, payout scheduled to the instructor's Stripe Connect account, FCM notification sent.
6
Sync into RoomApp refreshes the booking; UI switches from pending to confirmed. Conflicts always resolve in favour of the server.

Data model & offline behaviour

Room / SQLite tables

GroupTables
Identityusers, instructor_profiles, martial_art_styles, credentials
Gym programgyms, gym_programs, program_schedules, coach_requirements
Marketplacelesson_listings, availability_slots, bookings, payments, payouts
Trustreviews, review_media, reports, disputes, support_tickets
Communityforum_groups, group_members, posts, comments, post_likes
Systemnotifications, analytics_events, dashboard_widgets, outbox
Indexes on bookings(student_id, starts_at), availability_slots(listing_id, starts_at), posts(group_id, created_at) and reviews(instructor_id, rating). Foreign keys on; versioned migrations from v1.
Gym-specific fields: gym_programs stores day_of_week, style_id, title and ruleset (ADCC / ACBJJ Battle Jiu-Jitsu / Gi / No-Gi / open mat); coach_requirements stores required_style, minimum_credential, ruleset_experience, budget_cents and status; credentials stores type, issuing_body, rank or licence number, verified_by and document_url. All credential documents are validated by admins before a coach appears in shortlists.

Offline write queue

Local mutations are inserted into outbox with an idempotency key. WorkManager replays them under network constraints; the server rejects stale versions and returns conflict errors.

Editable offlineProfile, post, review text, support ticket, report — saved locally and queued
Requires networkSearch/autocomplete, booking, payment authorisation
Conflict policyServer wins for bookings and payments; field-level last-write-wins for profile and post text

Matching score — documented in the UI

30%Style match
25%Availability overlap
15%Distance from student
15%Rating & review quality
10%Price fit vs budget
5%Verification & response rate

Computed server-side in /functions/v1/match-instructors; the client displays factor breakdowns so rankings stay explainable and defensible. For gym sourcing, an additional mandatory gate runs first: the coach must hold the requested verified credential (for example Judo black belt or Kyokushin black belt) and the required ruleset experience (ADCC or ACBJJ Battle Jiu-Jitsu). Only gated candidates are scored.

06

Security, accessibility & quality

Security & privacy

  • Access/refresh tokens in Keystore-backed storage; cleared on logout.
  • HTTPS only; certificate pinning for production.
  • RLS: users own rows only, students own bookings, instructors own listings, reviews tied to completed bookings.
  • Upload allowlists: 10 MB images, 100 MB videos, server re-scan.
  • Runtime permissions requested just-in-time; PDPA-aligned notice and deletion requests.

Accessibility

  • Minimum 48 dp touch targets across the app.
  • TalkBack labels for icon buttons, ratings and status chips.
  • Text scaling support; no information conveyed by colour alone.
  • Keyboard/focus order tested for Compose navigation.
  • Accessibility Scanner in the release checklist.

Testing plan

  • Unit: ViewModels, price/commission, score formatter.
  • Room: DAO, migrations, foreign keys, outbox replay.
  • Network: MockWebServer contracts and error mapping.
  • Compose UI: navigation and form validation tests.
  • E2E: Maestro register → search → book → pay → review; join → post → comment.

Acceptance criteria for the Android client

1New user registers, logs out, resets a password and restores a session after restart.
2Instructor publishes a lesson and availability slots that appear in student search.
3Student searches, opens an instructor, selects a slot, pays with a Stripe test card and sees a confirmed booking.
4A completed booking can be rated once with text and optional media.
5Reports, disputes and support tickets submit offline and sync when connectivity returns.
6Forum posts, comments and likes work with role-aware access and optimistic UI.
7Dashboard widgets toggle and reorder, with Today/Week/Month ranges.
8No payment secrets or other users' private data are stored in SQLite.
9The gym can publish the Mon–Sun curriculum and see four open coach requirements with mandatory credentials and rulesets.
10Coach shortlists exclude candidates without a verified Judo / Kyokushin black belt or equivalent credential, and show ADCC / ACBJJ Battle Jiu-Jitsu experience where required.
11A coach can be booked for Wed Judo, Thu Wrestling (ADCC) or Fri Striking (ACBJJ Battle Jiu-Jitsu) with the correct ruleset stored on the booking.
